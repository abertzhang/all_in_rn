- 方案：用 `react-native` 核心自建轻量路由容器 `src/navigation/NavigationContainer.tsx`——react state 维护页面栈，`navigate()` 入栈 / `goBack()` 出栈，Context 提供 `useNavigation()`；顶栏带返回按钮。纯 JS，无任何第三方原生依赖，Android/Harmony 通用。

## Render Error 根因定位 + 修复（实机验证通过）

- 实机 `adb logcat` 抓到确切根因：`Error: Text strings must be rendered within a <Text> component.` in `View (created by App)`。
- 真因：`App.tsx` / `ViewCompPage.tsx` 第 20 行 `// ScrollView 作为根容器...` 写在 `return (` 之后、`<ScrollView>` 之前的 **JSX children 区域**（不在 `{}` 表达式内）。babel 不把它当 JS 注释，而是当成**裸文本字符串节点**渲染 → RN 报红屏。其余 `//` 注释都在 `style={{...}}` 对象内（合法行注释），无碍。
- 为何 jest 没抓到：之前用 `react-test-renderer` 渲染冒烟测试 PASS，是因为该渲染器**不校验“字符串必须在 <Text> 内”**；真机 Hermes + RN 原生渲染器才严格抛错。
- 修复：两文件都把该 `//` 行注释改为 JSX 块注释 `{/* ... */}`。
- 实机验证：force-stop 后冷启动，logcat 出现 `ReactNativeJS: Running "all_in_rn"` 且**无任何 Render/Invariant/Text-strings 错误**，App 正常渲染（PID 22541）。修复确认生效。
- 附带坑（与本次 JS 修复无关）：`npx react-native run-android` 偶发 Gradle 失败 `react-native-safe-area-context/android/build.gradle:105 No such property: directories for class: DefaultAndroidSourceDirectorySet`（该库与当前 AGP 版本不兼容；run8 缓存命中过关、run9 重新配置报此错）。验证时用「Metro 直接 `am start` 已装 APK」绕开 gradle。用户若自己 run-android 遇此错，需另修 safe-area-context 的 AGP 兼容（在 node_modules 内，待用户授权再动）。
