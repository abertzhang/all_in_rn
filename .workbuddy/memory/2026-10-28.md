# 2026-10-28 工作日志

## 修复 VSCode 打开项目报错（TS 类型检查整片标红）

**现象**：VSCode 打开项目后大量红色报错，集中在 `node_modules` 里的 `@types/node`。

**根因（两处叠加）**：
1. **`@types/node` 版本过新 + TS 过旧**：工程 `typescript` 固定在 `4.8.4`，但 `node_modules` 实际装的是 `@types/node@26.6.5`，其 `ffi.d.ts` 用了 `const T extends ...`（TS 5.0 的 const 类型参数语法）→ TS 4.8.4 解析不了，报 50 个 `TS1139/TS1005` 语法错误。
   - 注意：`package.json` 原有的 `overrides: { "@types/node": "^20" }` 是 **npm 语法**；本工程 `node_modules` 是 **pnpm** 装的，pnpm **不读根级 overrides**，只认 `pnpm.overrides`，所以该 override 一直被忽略，`@types/node` 按传递依赖解析成了 26.6.5。
   - 修复：在 `package.json` 加 `"pnpm": { "overrides": { "@types/node": "20.10.5" } }`（钉到 20.11.0 之前最后一个 20.x，确保不含 const 类型参数），改后需 `pnpm install` 才能让 pnpm 真正重解析。
2. **`@jest/globals` 顶层缺失**：测试文件 `__tests__/App.test.tsx` `import { it } from '@jest/globals'`。之前用 npm（扁平 node_modules）时 `@jest/globals` 被 hoist 到顶层可解析；换成 pnpm（隔离 node_modules）后它只是 jest 的传递依赖、顶层无软链 → `TS2307: Cannot find module '@jest/globals'`。
   - 修复：把 `"@jest/globals": "29.7.0"` 加进 `devDependencies`（与 jest 29.7.0 对齐），`pnpm install` 后顶层链接上。

**校验**：`tsc --noEmit` → `TSC_EXIT=0`；eslint 0 error（仅 376 条常态化 inline-style 警告）。

**结论/提醒**：
- 本工程用 **pnpm**（证据：`node_modules/.pnpm` store + `pnpm-lock.yaml`），但仓库同时残留 npm 的 `package-lock.json`。凡改依赖版本/override 必须走 pnpm，且 override 要写成 `pnpm.overrides` 而非根级 `overrides`。
- VSCode 报错修好后，需在 VSCode 里 `Cmd+Shift+P` → `TypeScript: Restart TS Server`（或重开项目）让 TS 语言服务重新加载。
- `.vscode/settings.json` 未强指定 `typescript.tsdk`，VSCode 自动用本工程 `node_modules/typescript` 4.8.4，符合预期。

## 修复 `pnpm react-native run-android` 报错（三连坑，全部同源于 npm→pnpm 迁移）

**坑 1：Gradle 找不到 `native_modules.gradle`**（`settings.gradle` 第 2 行按顶层路径读 `@react-native-community/cli-platform-android/native_modules.gradle`）。
- pnpm 隔离式 node_modules 不把这个包挂顶层。**RN + pnpm 标准修法**：项目根新建 `.npmrc` 写 `node-linker=hoisted`（+ `strict-peer-dependencies=false`），重装后 node_modules 变扁平（真实目录、非软链），`settings.gradle`/`app/build.gradle` 的全部顶层路径引用（native_modules.gradle、@react-native/gradle-plugin、react-native）都能解析。

**坑 2：Metro 红屏 500 `Unable to resolve module react-native`**。
- 根因是 **重装 node_modules 之前启动的老 Metro 进程**（PID 96068）watcher 失效。杀掉重启 Metro 后 bundle 正常（HTTP 200 / 5.98MB，冷启动约 118s）。
- 教训：**凡重建过 node_modules，必须重启 Metro**。

**坑 3：Gradle 下载依赖失败**——先 `kotlin-gradle-plugin-1.7.22-gradle71.jar ... Tag mismatch!`（缓存文件损坏，删 `~/.gradle/caches/modules-2/files-2.1/org.jetbrains.kotlin/kotlin-gradle-plugin/1.7.22/` 重下即好）；后 `bcprov-jdk15on-1.67.jar Read timed out`（直连 Maven Central 超时）。
- 修复：`android/build.gradle` 的 `buildscript.repositories` 最前面加阿里云镜像（central/google/gradle-plugin/public 四个），`google()`/`mavenCentral()` 保留兜底。

**最终验证**：`BUILD SUCCESSFUL in 13m51s`（首次全量+补依赖），重拉 app 后 `I ReactNativeJS: Running "all_in_rn" with {"rootTag":11}`，错误签名（Requiring unknown module / Unable to resolve / FATAL / redbox）全部为空 ✅。

**本工程工具链结论（以后照此执行）**：
- 包管理器用 **pnpm + `node-linker=hoisted`**（`.npmrc` 已建）；RN 0.72 的 Gradle 脚本硬依赖顶层 node_modules 路径，严禁用 pnpm 默认隔离模式。
- 重建 node_modules 后必须重启 Metro；Gradle 缓存损坏（Tag mismatch）删对应 `~/.gradle/caches/modules-2/files-2.1/<group>/<artifact>/<version>/` 重下。
- Maven 依赖走阿里云镜像（已在 `android/build.gradle` 配好）。
